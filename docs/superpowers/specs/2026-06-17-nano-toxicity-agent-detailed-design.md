## 2. 项目背景与问题定义

### 2.1 背景

纳米材料已经广泛用于肿瘤药物递送、影像诊断、局部治疗和联合治疗等方向。与传统小分子药物相比，纳米载体能够通过调节粒径、表面电荷、表面修饰和材料组成来改变药物在体内外环境中的行为，因此在肿瘤治疗中具有明显潜力。

但纳米材料的潜力并不等于安全。不同材料在不同细胞模型、不同剂量和不同暴露时间下，可能表现出显著不同的细胞毒性。如果在早期筛选阶段缺少一套结构化的初筛工具，研究者往往需要依赖大量文献查找、经验判断和重复实验来判断候选材料是否值得继续推进。这一过程通常存在三个问题：

- 信息分散：毒性相关数据分散在数据库、论文和不同实验体系中。
- 决策成本高：研究者需要人工综合材料性质、细胞类型和实验条件。
- 解释困难：即使得到一个模型预测结果，也需要说明“为什么得到这个结论”。

因此，本项目希望构建一个可运行的 Web 智能体原型，在不替代真实实验的前提下，为纳米材料细胞毒性初筛提供辅助判断、解释和建议。

### 2.2 核心问题

本项目要解决的问题可以概括为：

> 给定纳米材料的理化性质、暴露条件和细胞实验背景，能否快速输出一个可解释的体外细胞毒性风险判断，用于支持肿瘤纳米药物筛选阶段的早期决策？

这个问题包含两个层面：

1. `预测层面`
   - 输入材料参数与实验条件。
   - 输出细胞活力估计与毒性等级判断。

2. `解释层面`
   - 说明哪些特征对判断影响最大。
   - 给出风险建议和文献依据。
   - 在有 LLM 的情况下，生成更自然、更适合汇报或阅读的解释文本。

### 2.3 为什么要聚焦“体外细胞毒性”

本项目选择“体外细胞毒性”而不是更大的“纳米药物安全性预测”，原因有三点：

- 第一，体外细胞毒性是公开数据相对更容易获得、标签相对更清晰的起点。
- 第二，课程原型需要可运行、可验证、可解释，体外任务更适合作为第一版。
- 第三，体内毒性、药代动力学、免疫反应和长期蓄积涉及更多变量，不适合在第一版中一次性覆盖。

因此，本文档中的“毒性”默认指向：

> 纳米材料在体外细胞实验中的细胞毒性风险，而不是人体临床毒性，也不是药物疗效。

## 3. 项目目标、边界与非目标

### 3.1 项目目标

本项目的目标是构建一个面向课程演示与研究原型验证的纳米毒性预测智能体，具备以下能力：

- 接收用户输入的纳米材料参数与实验条件。
- 输出体外细胞活力预测值。
- 输出低毒、中毒、高毒的分类结果。
- 展示模型置信度与关键影响因素。
- 结合规则和本地文献摘要生成解释与建议。
- 在配置 LLM API 时输出更自然的说明文本。
- 在未配置 LLM 时依然保持可运行和可解释。

### 3.2 明确边界

系统边界需要在汇报中讲清楚，否则容易被误解为“AI 自动判断药物是否安全”。

本系统的边界如下：

- 预测对象是 `体外细胞实验结果`。
- 输出是 `早期风险辅助判断`，不是最终科研结论。
- 预测来源是 `机器学习模型`，不是 LLM。
- 文献依据来自 `本地固定文献摘要库`，不是在线自由生成。
- 系统不负责药效预测，不负责肿瘤分型，不直接推荐治疗方案。

### 3.3 非目标

以下内容不属于第一版原型目标：

- 体内毒性预测。
- 临床不良反应预测。
- 自动检索全网文献并形成研究结论。
- 端到端自主实验设计智能体。
- 医疗监管或临床决策支持系统。

## 4. 目标用户与使用场景

### 4.1 目标用户

本项目主要面向三类用户：

1. `课程汇报者或答辩者`
   - 需要展示一个完整、可运行、可解释的 AI 研究原型。

2. `实验室研究者`
   - 希望在正式实验前对候选纳米材料进行初筛。

3. `技术实现者`
   - 需要根据方案完成数据整理、模型训练和 Web 原型开发。

### 4.2 典型使用场景

场景一：研究人员已有若干候选纳米载体，希望优先筛掉高风险方案。

场景二：课程展示中，需要向评审演示“从输入材料参数到输出毒性结论和解释”的完整链路。

场景三：用户希望追问“为什么粒径重要”“为什么同样剂量下不同材料预测结果不同”，系统需要给出结构化解释。

### 4.3 典型使用流程

```text
输入纳米材料与实验信息
→ 系统检查格式与范围
→ 进行特征处理
→ 模型输出细胞活力与毒性等级
→ 系统展示关键影响因素
→ 结合规则与文献生成解释
→ 用户阅读结论或继续追问
```

## 5. 总体架构设计

### 5.1 总体思路

系统采用轻量化分层架构，将“预测”与“解释”明确分开：

- 预测由传统机器学习模型负责。
- 解释由规则、特征重要性和文献摘要共同支撑。
- LLM 只在最后一层负责自然语言组织，不参与数值预测。

这种架构的优点是：

- 科学边界更清楚。
- 系统在无 LLM 环境下依旧可运行。
- 更容易向评审解释“哪些结果可信、哪些结果只是表达增强”。

### 5.2 架构流程

```text
用户输入层
→ 数据校验与特征工程层
→ ML 模型预测层
→ 解释上下文构造层
→ 可选 LLM 解释层
→ 智能体输出层
```

### 5.3 各模块职责

| 模块 | 作用 | 关键输出 |
| --- | --- | --- |
| Web UI | 接收输入、触发预测、展示结果 | 页面表单、结果卡片、解释区 |
| 数据处理层 | 检查格式、统一单位、编码变量 | 模型可接收的特征向量 |
| 模型服务层 | 加载分类和回归模型 | 毒性等级、细胞活力、置信度 |
| 解释引擎 | 汇总特征重要性、规则、文献摘要 | 结构化解释上下文 |
| 可选 LLM 层 | 组织更自然的说明文本 | 报告式解释与建议 |
| 文献知识库 | 提供固定、可追溯的依据 | 标题、用途、关键结论、链接 |

## 6. 数据方案与数据治理

这一章是汇报中的重点，因为模型是否可信，首先取决于数据是否合理。对非机器学习背景的汇报人来说，可以把“数据方案”理解为回答以下问题：

> 模型是用什么数据学出来的？这些数据代表什么？数据是否统一、可比、可信？

### 6.1 为什么数据是核心

机器学习模型并不是凭空“理解毒性”。它本质上是在历史样本中学习“输入特征”和“实验结果”之间的对应关系。

例如，如果历史数据反复显示：

- 高剂量更容易降低细胞活力；
- 某些材料组成在特定细胞系上更容易表现出毒性；
- 粒径和表面电荷在细胞摄取或膜相互作用中起重要作用；

那么模型就会从这些样本中学习出一种统计规律，并在新样本到来时做出预测。

因此，数据方案的好坏直接决定：

- 模型能不能学到合理规律。
- 预测有没有泛化能力。
- 最后解释时是否站得住脚。

### 6.2 一个样本在本项目中代表什么

在本项目里，一条样本可以理解为：

> 某一种纳米材料在某一种实验条件和某一种细胞背景下，对应的一次体外细胞毒性观察记录。

也就是说，一条样本不仅包含“材料是什么”，还包含：

- 材料有哪些理化性质。
- 在什么剂量下暴露。
- 暴露多长时间。
- 用什么细胞系。
- 最终观察到多少细胞活力，或者对应什么毒性等级。

这个定义很重要，因为它说明模型学的不是“材料本身是否有毒”，而是：

> 在给定实验条件下，这个材料组合表现出的毒性结果。

### 6.3 推荐数据来源

第一版原型推荐从以下来源中优先选择可结构化、可清洗的数据：

1. `eNanoMapper`
   - 适合纳米材料安全、毒理和性质数据。
   - 用于支撑纳米毒性机器学习任务。

2. `caNanoLab`
   - 与癌症纳米技术相关，更能体现“肿瘤纳米药物筛选”的应用背景。
   - 可用于丰富材料类型、实验背景和项目叙事。

3. `已公开整理的数据集或文献附表`
   - 如果原始数据库字段过于复杂，可先采用已有结构化数据作为第一版训练集。
   - 目标是保证课程原型能先跑通。

### 6.4 为什么需要统一 schema

来自不同数据库或论文的数据通常不能直接拼在一起使用，原因包括：

- 同一个字段命名不同，例如“particle size”“diameter”“hydrodynamic size”。
- 单位不同，例如剂量可能是 `μg/mL`、`mg/L` 或 `ppm`。
- 类别写法不同，例如 `PEGylated`、`PEG`、`PEG-coated` 可能本质相同。
- 标签标准不同，例如有的记录给出细胞活力百分比，有的只给“有毒/无毒”。

因此，需要先建立一个统一字段体系，也就是统一 schema。它相当于先规定好：

> 所有样本进入模型之前，必须用同一套字段、同一套单位和同一套标签标准来描述。

### 6.5 建议的统一字段

| 字段 | 类型 | 说明 | 为什么重要 |
| --- | --- | --- | --- |
| 材料类型 / 组成 | 分类 | 金属、氧化物、聚合物、脂质体、碳基等 | 不同材料的毒理机制不同 |
| 粒径 | 数值 | 单位统一为 nm | 影响细胞摄取与分布行为 |
| Zeta 电位 | 数值 | 单位统一为 mV | 影响表面电荷与细胞相互作用 |
| 表面修饰 | 分类 | PEG、柠檬酸盐、无修饰等 | 影响稳定性和生物相容性 |
| 暴露剂量 | 数值 | 单位统一 | 常是毒性最直接的影响因素 |
| 暴露时间 | 数值 | 单位 h | 决定暴露强度和累积效应 |
| 细胞类型 | 分类 | A549、HepG2、BEAS-2B 等 | 不同细胞对材料敏感性不同 |
| 来源物种 | 分类 | Human、Mouse、Rat 等 | 增强实验背景区分度 |
| 组织来源 | 分类 | Lung、Liver、Kidney 等 | 不同组织来源反应不同 |
| 检测方法 | 分类 | MTT、LDH 等 | 不同方法可能带来标签差异 |

### 6.6 输出标签如何设计

本项目采用“双输出”方案：

1. `回归输出`
   - 预测细胞活力百分比，例如 `85%`。
   - 这是一个连续值，更接近实验原始观察。

2. `分类输出`
   - 将细胞活力映射为 `低毒 / 中毒 / 高毒`。
   - 更适合前端展示、汇报表达和辅助筛选。

毒性等级阈值建议如下：

```text
细胞活力 >= 80%：低毒
50% <= 细胞活力 < 80%：中毒
细胞活力 < 50%：高毒
```

这里需要在汇报中说明：

- 这个阈值是课程原型中的统一标准。
- 它有助于把连续结果转为更易理解的等级。
- 但正式研究中仍应根据具体实验标准或文献定义调整。

### 6.7 数据清洗的基本思路

数据清洗不是“额外工作”，而是模型训练前必须完成的基础步骤。对非技术背景的汇报人，可以这样理解：

> 如果输入数据不统一，模型看到的就不是科学规律，而是混乱格式。

建议的数据清洗流程如下：

1. `字段筛选`
   - 仅保留与毒性预测直接相关的字段。

2. `单位统一`
   - 例如将粒径统一为 nm，暴露时间统一为 h，剂量统一为一个浓度单位。

3. `类别标准化`
   - 合并同义标签，例如不同写法的 PEG 修饰。

4. `缺失值处理`
   - 丢弃关键字段严重缺失的样本。
   - 对非核心字段可采用“未知”类别或统计补全。

5. `异常值检查`
   - 对极端不合理值进行筛查，例如负剂量、明显错误的粒径。

6. `标签构造`
   - 若原始数据只有细胞活力百分比，则进一步映射为毒性等级。

### 6.8 为什么要避免数据泄漏

数据泄漏是机器学习中很常见但容易被忽略的问题。简单理解：

> 模型在训练时不应该提前看到测试阶段本不该知道的信息。

例如，如果先用全量数据做标准化，再划分训练集和测试集，就会把测试集的信息提前暴露给模型。这样得出的评估结果会虚高，看起来很准，实际上落地后不一定有效。

因此，正确流程应该是：

```text
先划分训练集 / 测试集
→ 再只用训练集拟合预处理器
→ 再把同样的预处理应用到测试集
```

### 6.9 训练集、验证集、测试集的意义

为方便汇报，可以用下面的类比：

- `训练集`：模型用来“学习”的数据。
- `验证集`：模型调参数时用来“比较方案”的数据。
- `测试集`：最后真正检验效果的数据。

如果数据规模不大，也可以采用交叉验证。其思想是：

> 不只切一次训练/测试，而是轮流切多次，让评估更稳定。

### 6.10 类别不平衡问题

真实数据中常见情况是：低毒样本比高毒样本多得多。如果不处理，模型可能学会“多数类偏好”，即总是预测低毒，看起来准确率不低，但对真正重要的中毒或高毒样本识别能力很差。

可以采取的处理方式包括：

- 使用分层抽样保证划分后类别比例相近。
- 在训练时设置类别权重。
- 使用 F1、Recall 等比 Accuracy 更能反映风险识别能力的指标。

### 6.11 数据治理建议

为了让后续汇报更专业，建议在工程中显式保留以下内容：

- 每条样本的数据来源。
- 每个字段的单位说明。
- 每一步清洗规则。
- 被删除样本的原因记录。
- 训练集与测试集的划分方式。

这部分内容不一定全部展示在前端，但在答辩或评审中非常重要，因为它体现了数据的可追溯性和研究过程的规范性。

## 7. 模型方案与实验评估设计

这一章需要帮助非机器学习背景的汇报人回答以下问题：

> 模型是什么？为什么选这个模型？它怎么训练？结果怎么理解？为什么说它有一定可信度？

### 7.1 为什么要同时做回归和分类

本项目不是只输出一个“有毒/没毒”的判断，而是采用双模型方案：

- `回归模型`预测细胞活力百分比。
- `分类模型`预测低毒、中毒、高毒。

这样设计有两个好处：

第一，回归结果更贴近原始实验数据。  
例如输出 `63%` 这样的结果，更容易与实验测量值对应。

第二，分类结果更适合产品展示和筛选决策。  
例如“中毒”比“63%”更便于汇报时快速表达风险等级。

可以把它理解为：

> 回归模型负责给出更细的数值估计，分类模型负责给出更直观的风险标签。

### 7.2 第一版为什么选择随机森林

第一版推荐使用：

- `RandomForestRegressor`
- `RandomForestClassifier`

随机森林可以向非技术背景这样解释：

> 它不是只靠一棵决策树做判断，而是让很多棵树分别给出判断，再通过投票或平均得到最终结果。

这种方法的优点是：

- 比单棵决策树更稳定，不容易因为少量样本变化而剧烈波动。
- 对数值特征和类别特征都比较友好。
- 对非线性关系有较强适应能力。
- 能给出特征重要性，便于解释。
- 在中小规模结构化数据上通常表现稳健。

### 7.3 为什么不把深度学习作为第一版主模型

在汇报中经常会被问到：“为什么不用更先进的深度学习？”

建议回答逻辑如下：

- 第一版数据规模通常不够大，深度学习不一定比传统模型更稳。
- 当前任务是结构化表格数据，不是图像、文本或超大规模序列数据。
- 课程原型更强调可运行、可解释、可演示，而不是追求最复杂算法。
- 随机森林更容易调试、更容易展示特征重要性，也更便于向非专家说明。

因此，第一版优先选择稳健、解释性较好的结构化数据模型，是一个务实而合理的工程决策。

### 7.4 训练流程的直观解释

模型训练流程可以用下面的方式讲解：

```text
整理好历史样本
→ 把样本转换成模型可读的数字表示
→ 用一部分样本训练模型
→ 用另一部分样本测试模型是否学到规律
→ 保存效果较好的模型
```

更细化的训练过程如下：

1. 读取原始数据。
2. 清洗字段、统一单位和标签。
3. 划分训练集与测试集。
4. 对数值特征做标准化，对分类特征做编码。
5. 训练分类模型与回归模型。
6. 在测试集上评估效果。
7. 保存模型和预处理器，供前端调用。

### 7.5 特征工程为什么必要

模型不能直接理解“PEG”“A549”这样的文本标签，因此需要把它们转成机器可处理的形式。这就是特征工程的一部分。

常见处理方式包括：

- `分类变量编码`
  - 例如把材料类型、细胞类型、表面修饰转成数值表示。

- `数值变量标准化`
  - 让不同量纲的特征更容易被模型处理。

- `标签构造`
  - 将细胞活力映射为毒性等级。

在汇报中可以强调：

> 特征工程不是“人为操纵结果”，而是把实验信息整理成模型能理解的格式。

### 7.6 建议的模型对比策略

虽然第一版最终主模型建议是随机森林，但为了说明选择过程更有依据，建议加入对比模型：

- `DecisionTree`
  - 作为简单、可解释的基线模型。

- `Logistic Regression / Linear Regression`
  - 作为线性基线，帮助判断问题是否需要更复杂模型。

- `XGBoost`
  - 作为性能对比模型，观察是否在结构化数据上有进一步提升。

这样在汇报中就可以说明：

> 我们不是直接拍脑袋选模型，而是先用多个代表性方法对比，再根据效果、稳定性和可解释性选择第一版主模型。

### 7.7 评估指标应该怎么讲

这一部分对非机器学习背景很关键。建议不是只念英文缩写，而是解释“这些指标分别回答什么问题”。

#### 分类任务指标

1. `Accuracy`
   - 所有样本中，预测正确的比例。
   - 直观，但在类别不平衡时可能不够可靠。

2. `Precision`
   - 被模型判成某类的样本中，真正属于该类的比例。
   - 适合回答“模型说高毒时，有多大概率真的是高毒”。

3. `Recall`
   - 某类真实样本中，被模型成功识别出来的比例。
   - 适合回答“真正的高风险样本，有多少没有漏掉”。

4. `F1`
   - Precision 和 Recall 的综合平衡指标。
   - 当既希望少误报、又希望少漏报时很有用。

5. `Confusion Matrix`
   - 展示各类别之间具体错分到了哪里。
   - 比单一准确率更适合汇报，因为能看出“中毒容易被错分成低毒还是高毒”。

#### 回归任务指标

1. `MAE`
   - 平均绝对误差。
   - 可以理解为“预测值和真实值平均相差多少个百分点”。

2. `RMSE`
   - 对较大误差更敏感。
   - 如果 RMSE 明显大于 MAE，说明模型可能在少数样本上偏差较大。

3. `R²`
   - 反映模型对整体变化趋势的解释能力。
   - 越接近 1，说明模型越能解释数据变化。

### 7.8 如何解释“模型置信度”

汇报中常见的一个误区是把“置信度”说成“模型有 91% 的概率绝对正确”。这种说法不严谨。

更准确的说法是：

> 在分类模型中，置信度通常表示模型内部对当前类别判断的相对把握程度，例如投票比例或概率估计。

它可以帮助用户判断：

- 当前样本是“明显偏向某一类”，还是“处于边界区域”。
- 是否需要更加谨慎地解读结果。

因此，置信度适合用来表达“不确定性高低”，但不应被解释为临床意义上的确定概率。

### 7.9 如何解释“特征重要性”

特征重要性表示：

> 在模型整体判断过程中，哪些输入变量对结果影响更大。

例如，如果剂量、粒径和 Zeta 电位的重要性更高，说明模型在大量样本中更依赖这些信息来区分毒性结果。

但汇报中要补一句关键说明：

- 特征重要性反映的是统计层面的影响程度。
- 它不等于严格因果关系。
- 它更适合作为“解释线索”，而不是单独作为生物机制结论。

### 7.10 单样本解释与全局解释的区别

如果只展示随机森林特征重要性，那么展示的是“全局解释”，即模型整体上更关注什么特征。

如果未来引入 SHAP 或 LIME，则可以补充“局部解释”，即：

> 对当前这个具体样本来说，哪些因素把结果推向了低毒，哪些因素把结果推向了高毒。

这部分可以在汇报中作为改进方向来讲，因为它会显著增强说服力。

### 7.11 推荐实验设计

为了让模型选择更有证据，建议在实验设计中明确以下内容：

- 使用固定随机种子，保证实验可复现。
- 使用训练集/测试集分离或交叉验证。
- 对比多个基线模型。
- 同时报告分类和回归效果。
- 展示代表性错误案例。
- 展示特征重要性排序。

### 7.12 结果展示建议

在未来汇报或报告中，建议至少补齐以下结果材料：

- 数据集基本统计表。
- 分类指标对比表。
- 回归指标对比表。
- 混淆矩阵图。
- 细胞活力预测误差示意图。
- 特征重要性条形图。
- 2 到 3 个案例分析。

这些内容会显著增强“模型不是黑盒演示，而是有实验支撑的原型”这一印象。

## 8. 解释系统与 LLM 边界控制

### 8.1 为什么需要解释层

仅输出“低毒”或“中毒”很难支持科研场景，因为用户还会继续问：

- 为什么是这个结果？
- 哪些特征起了主要作用？
- 是否值得进入下一轮实验？

因此，系统需要一个单独的解释层，把预测结果转化为研究者可以理解和讨论的文字说明。

### 8.2 解释层的组成

解释层建议由四类信息共同构成：

- 模型输出结果。
- 特征重要性或关键因素。
- 规则化解释模板。
- 本地文献摘要依据。

### 8.3 为什么 LLM 只能做“表达增强”

LLM 的优势是语言组织能力强，能够把结构化结果改写成更自然、更适合阅读的说明文本。但它的弱点是：

- 可能编造没有提供的数据来源。
- 可能把不确定的结论说得过于肯定。
- 可能混淆模型预测和文献常识。

因此，本文档明确规定：

> LLM 不参与预测，不决定毒性等级，不生成未提供的文献事实，只能基于已有上下文做表达增强。

### 8.4 模板解释与 LLM 解释的关系

系统需要同时支持两种解释模式：

1. `模板解释`
   - 无需外部 API。
   - 结果稳定、结构固定、最适合保证系统可运行。

2. `LLM 增强解释`
   - 在模板和结构化上下文基础上进行自然语言重写。
   - 更适合演示、报告和用户追问。

在汇报中要强调：

> 即使没有 LLM，本系统依旧能完成预测与解释；LLM 是增强层，不是依赖核心。

## 9. 智能体交互与 Web 原型设计

### 9.1 为什么用 Web 原型

课程项目和原型验证的关键，不只是模型训练完成，还要让使用者能“看到输入、触发结果、理解解释”。因此，Web UI 不是附属部分，而是智能体体验的重要入口。

### 9.2 推荐交互流程

推荐页面包括两个核心区域：

- `输入区`
  - 材料属性、暴露条件、细胞背景、是否启用 LLM 增强。

- `结果区`
  - 毒性等级、细胞活力、置信度、关键因素、解释与建议、文献依据。

### 9.3 结果态应该呈现什么

一次成功预测后，页面建议展示：

- 研究结论卡。
- 样本信息摘要。
- 特征影响排序。
- 解释与建议。
- 文献依据与链接。

这样能让用户从“结论”“输入背景”“原因”“下一步建议”四个层次理解结果。

## 10. 文献依据与知识库设计

### 10.1 为什么要有本地文献库

如果解释完全依赖 LLM 自由生成，系统很难保证科学表述的可追溯性。引入本地固定文献摘要库的目的，就是为系统提供受控、可引用的知识来源。

### 10.2 每篇文献建议保留的信息

每篇文献建议至少包含：

- 标题
- 年份
- 用途
- 关键结论
- 可引用链接

### 10.3 文献库在系统中的作用

文献库主要起三种作用：

- 为设计方案提供理论依据。
- 为解释文本提供可追溯支撑。
- 为后续答辩或汇报准备引用素材。

## 11. 系统可信性、风险与局限

### 11.1 可信性来自哪里

本系统的可信性主要来自以下四点：

- 预测由机器学习模型输出，而非语言模型臆断。
- 数据字段、单位和标签经过统一。
- 解释中引用的依据来自本地固定文献库。
- 系统明确区分“预测结果”和“语言表达”。

### 11.2 主要风险

当前方案的主要风险包括：

- 数据规模可能较小。
- 不同实验体系之间存在异质性。
- 不同检测方法带来的标签偏差可能影响训练。
- 特征重要性不等于因果机制。
- LLM 在上下文不足时仍可能出现表达偏差。

### 11.3 需要在汇报中明确承认的局限

汇报时应主动说明：

- 本系统是研究原型，不是临床系统。
- 结果适用于体外初筛，不代表体内安全性。
- 第一版重点是可运行和可解释，不追求覆盖全部毒理终点。

这种主动限定边界，通常比夸大能力更有说服力。

## 12. 工程实现、部署与运行模式

### 12.1 推荐技术栈

- Python
- pandas / numpy
- scikit-learn
- joblib
- Streamlit
- matplotlib / seaborn
- 可选 LLM API

### 12.2 为什么选 Streamlit

因为第一版核心目标是“快速构建一个可交互演示原型”，而不是开发一个复杂前后端分离系统。Streamlit 的优势是：

- 开发速度快。
- 与 Python 模型代码衔接自然。
- 适合表单输入、图表展示和结果说明。
- 对课程答辩和内部演示足够友好。

### 12.3 运行模式

系统建议支持两种运行模式：

1. `基础模式`
   - 只使用本地模型与模板解释。
   - 不依赖外部 LLM 服务。

2. `增强模式`
   - 在基础模式上启用 LLM API。
   - 输出更自然的解释文本与追问回答。

## 13. 演示方案与验收标准

### 13.1 推荐演示脚本

汇报时建议按照下面顺序演示：

1. 简要介绍项目目标与边界。
2. 展示页面输入项。
3. 输入一个典型样本并触发预测。
4. 先讲毒性等级、细胞活力和置信度。
5. 再讲关键影响因素和解释文本。
6. 最后说明文献依据来自哪里。
7. 如启用 LLM，再展示增强解释与追问能力。

### 13.2 验收标准

原型验收建议至少满足：

- 用户可以在页面输入完整样本信息。
- 系统能输出细胞活力和毒性等级。
- 系统能展示主要影响因素。
- 无 LLM 时能输出模板解释。
- 有 LLM 时能输出增强解释。
- 文献依据可追溯到本地条目。

## 14. 迭代路线与后续研究方向

### 14.1 第一阶段：可交付原型

```text
Streamlit UI + 结构化数据集 + RandomForest 模型 + 模板解释 + 文献摘要库
```

目标是确保系统可运行、可演示、可解释。

### 14.2 第二阶段：增强解释与问答

```text
加入 LLM 增强解释 + 多轮追问 + 更完整的引用展示
```

目标是提升自然语言交互体验和汇报表现力。

### 14.3 第三阶段：增强可信性

```text
引入 SHAP/LIME + 更规范的数据治理 + 更强实验评估
```

目标是提高结果解释力和技术说服力。

### 14.4 第四阶段：升级为真正的工具型智能体

```text
引入 Agent 框架 + 文献检索/RAG + 报告生成 + 实验建议工具
```

目标是从“可解释预测原型”进一步升级为“研究辅助智能体”。

## 16. 总结

本项目的核心价值不在于“用一个大模型替代科研判断”，而在于构建一套边界清晰、可运行、可解释、适合展示的研究原型：

- 用结构化数据训练机器学习模型，完成纳米材料体外毒性初筛。
- 用规则、特征重要性和文献摘要支撑解释。
- 用可选 LLM 提升表达质量，而不接管预测权。

对于课程项目而言，这样的方案在技术复杂度、科学边界和演示效果之间取得了较好的平衡；对于后续研究而言，它也为数据扩展、解释增强、文献检索和智能体化升级保留了清晰路径。
